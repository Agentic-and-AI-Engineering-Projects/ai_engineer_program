What calls what, and the input/output type at every step · Phase 2 pipeline
The shape of the system
Three stage modules (filter.py, ranker.py, agent.py) each do one job and are independently testable. pipeline.py orchestrates them — it owns no matching logic, it just calls the stages in order and persists the result. db.py and data_loader.py are shared infrastructure.

How the smoke tests fit

Each module has an if __name__ == "__main__" block that exercises just that stage, so any one can be run in isolation. Each re-runs the earlier stages to build its own input — that is why agent.py's smoke test calls filter_candidates and rank_candidates first.

CommandTests
python -m matchscout.filterStage 1 alone
python -m matchscout.rankerStage 1 → Stage 2
python -m matchscout.agentStage 1 → 2 → 3 (both arms)
python -m matchscout.pipelinethe whole chain + DB writes

The only side effects (writes)

Every function is pure — returns a value, no writes — except the two db.* calls at the end of recommend_creators:

  • db.update_gig — flips the gig to in_review and records the treatment arm
  • db.insert_recommendations — writes the 3 recommendation rows

Stages 1, 2, and 3 never touch the database. The pipeline is the single place results are persisted.
