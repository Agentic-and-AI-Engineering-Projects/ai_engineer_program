1. Overview

What MatchScout Does

MatchScout is an AI-powered match-quality predictor for Onemyle's two-sided marketplace. Given a creator and a business, it predicts whether they're likely to have a successful collaboration — outputting a probability score, reasoning citing specific signals, risk factors, and a recommended action.

One-line description

"For Onemyle's marketplace operations team, MatchScout is an AI early-warning system that scores creator-business match quality before introduction, so we can recommend better matches, flag risky introductions, and reduce double-sided churn."

2. Problem Statement

The Problem MatchScout Solves

Marketplace dynamics

Onemyle is a two-sided marketplace. Both sides depend on match quality:

  • Creators waste effort pitching businesses that aren't a real fit → frustration, churn
  • Businesses get poor content from mismatched creators → frustration, churn
  • Marketplace loses transactions, GMV, reputation

Today, matching is largely manual or browse-based. Both sides spend time evaluating fit. Bad matches happen — and they cause double-sided churn.

What we're building toward

An AI layer that scores match quality automatically — informing recommendations, surfacing risky introductions for proactive support, and improving the overall marketplace experience.

4. Architecture (3-Stage Cascade)

3-Stage Cascade Pipeline

Industry-standard architecture for marketplace AI. Each stage filters by an order of magnitude, keeping cost and latency manageable while preserving premium reasoning quality where it matters most.

┌──────────────────────────────────────────────────────────────────┐ │ ALL POSSIBLE PAIRS │ │ 400 creators × 300 businesses = 120,000 possible pairs │ └──────────────────────────────────────────────────────────────────┘ │ ▼ ┌──────────────────────────────────────────────────────────────────┐ │ STAGE 1 — HARD FILTERS (rules-based) │ │ • Same OR adjacent category │ │ • Content type overlap (creator's outputs ∩ business's needs) │ │ • Location compatible (same metro OR remote-OK) │ │ • Budget overlap (creator's range ∩ business's range) │ │ • Both accounts active in last 30 days │ │ │ │ Cost: ~$0 (no LLM) Latency: ~10ms (DB query) │ │ Reduces: 120K → ~5-10K compatible pairs │ └──────────────────────────────────────────────────────────────────┘ │ ▼ ┌──────────────────────────────────────────────────────────────────┐ │ STAGE 2 — VECTOR SIMILARITY RANKING │ │ • Embed creator profile (sub-categories + niche tags + │ │ content types as text) │ │ • Embed business brief (needs + niche tags) │ │ • Cosine similarity → rank top 20-30 candidates per query │ │ • Uses sentence-transformers (all-MiniLM-L6-v2) locally │ │ │ │ Cost: ~$0 (embeddings cached) Latency: ~50ms │ │ Reduces: ~5-10K → top 20 candidates │ └──────────────────────────────────────────────────────────────────┘ │ ▼ ┌──────────────────────────────────────────────────────────────────┐ │ STAGE 3 — LLM AGENT (PREMIUM REASONING) │ │ • LangGraph state machine │ │ • Claude Sonnet 4.6 (primary) — premium model │ │ • Analyzes top 10-20 candidates with full context │ │ • Outputs: probability + reasoning + risk_flags + action │ │ │ │ Cost: ~$0.18 per pair Latency: ~2 sec per pair │ │ Per query (top 20): ~$3.60 + ~10s (sequential) │ │ Per query (parallelized): ~$3.60 + ~3s (with concurrency) │ └──────────────────────────────────────────────────────────────────┘ │ ▼ Final ranked matches with full reasoning

Why this architecture (vs alternatives)

AlternativeWhy we rejected
Pure LLM (no filters)120K pairs × $0.18 = $21,600/run. Not viable.
Pure rules (no LLM)Misses nuance. No reasoning. No "why this match" explanation.
Pure ML (gradient boost / NN)Requires labeled training data Onemyle doesn't have yet. No explainability.
Pure vector similarityCatches semantic fit but misses business context, budget, location. No reasoning.
3-stage cascadeBest of all: fast + cheap + smart + explainable.
5. Components — Detailed

Component Breakdown

filter.py — Stage 1 (Hard Filters)

def stage1_filter(creator, business) -> bool:
    """Pure function — returns True if pair is compatible enough to consider."""

    # Category compatibility (with adjacency map)
    if creator.primary_category != business.primary_category:
        if creator.primary_category not in ADJACENT_MAP[business.primary_category]:
            if business.primary_category not in (creator.secondary_categories or []):
                return False

    # Content type overlap
    if not set(creator.content_types) & set(business.content_needs):
        return False

    # Location compatibility
    if not creator.remote_friendly and creator.location != business.location:
        return False

    # Budget overlap
    if creator.budget_range[1] < business.budget_range[0]: return False
    if creator.budget_range[0] > business.budget_range[1]: return False

    # Activity check
    if not (creator.active_30d and business.active_30d): return False

    return True

No LLM calls. Pure rules. Runs in microseconds per pair.

ranker.py — Stage 2 (Vector Similarity)

from sentence_transformers import SentenceTransformer

model = SentenceTransformer("all-MiniLM-L6-v2")  # local, free, fast

def creator_text(creator):
    """Textual representation for embedding."""
    return f"{creator.primary_category} {' '.join(creator.subcategories)} " \
           f"{' '.join(creator.niche_tags)} {' '.join(creator.content_types)}"

def business_text(business):
    return f"{business.primary_category} {' '.join(business.subcategories)} " \
           f"{' '.join(business.niche_tags)} {' '.join(business.content_needs)}"

def stage2_rank(business, candidates, top_k=20):
    """Rank filtered candidates by cosine similarity to business."""
    business_vec = model.encode(business_text(business))
    candidate_vecs = model.encode([creator_text(c) for c in candidates])

    similarities = cosine_similarity([business_vec], candidate_vecs)[0]
    ranked = sorted(zip(candidates, similarities), key=lambda x: -x[1])
    return ranked[:top_k]

Embeddings can be pre-computed and cached. Uses sentence-transformers (free, local, no API costs).

agent.py — Stage 3 (LangGraph LLM Agent)

from langgraph.graph import StateGraph
from anthropic import Anthropic
from pydantic import BaseModel

class MatchPrediction(BaseModel):
    success_probability: float       # 0.0 - 1.0
    reasoning: str                    # explanation citing specific signals
    risk_factors: list[str]           # e.g., ["budget_mismatch", "first_time_business"]
    recommended_action: str           # "introduce" | "introduce_with_clarification" |
                                      # "hold_pending_review" | "do_not_introduce"

# LangGraph state machine
class AgentState(TypedDict):
    creator: dict
    business: dict
    compatibility_signals: dict       # computed signals
    prediction: MatchPrediction

def load_profiles(state): ...
def compute_signals(state): ...       # location overlap, budget alignment, etc.
def call_llm(state): ...              # Claude reasoning with structured output
def validate_output(state): ...       # ensure prediction matches schema

graph = StateGraph(AgentState)
graph.add_node("load", load_profiles)
graph.add_node("signals", compute_signals)
graph.add_node("predict", call_llm)
graph.add_node("validate", validate_output)
graph.add_edge("load", "signals")
graph.add_edge("signals", "predict")
graph.add_edge("predict", "validate")
graph.set_entry_point("load")
graph.set_finish_point("validate")

Structured output enforced via Pydantic. Multi-step state machine allows targeted retries (only re-run "predict" if validation fails, not re-run "load").

pipeline.py — Orchestrator

def find_matches_for_business(business_id, top_k=5):
    """Run the full cascade for a single business query."""
    business = load_business(business_id)
    all_creators = load_all_creators()

    # Stage 1
    candidates = [c for c in all_creators if stage1_filter(c, business)]

    # Stage 2
    ranked = stage2_rank(business, candidates, top_k=20)

    # Stage 3 (parallelized for latency)
    predictions = await asyncio.gather(*[
        agent.invoke({"creator": c, "business": business})
        for c, _similarity in ranked
    ])

    # Sort by predicted success probability
    final = sorted(predictions, key=lambda p: -p.success_probability)
    return final[:top_k]

10. Trigger Patterns

V1 (PoC) vs V2 (Production)

V1 — Manual / On-Demand

For the PoC, MatchScout is invoked manually:

# From CLI
python -m matchscout.pipeline --business biz_001 --top-k 5

# From Python
from matchscout import predict_matches
results = predict_matches(business_id="biz_001", top_k=5)

# From eval framework
python -m eval.run_golden_set    # runs cascade against all golden set entries

No automated triggering. No web service. CLI / function-call interface only.

V2 — Production Triggers (documented, not built)

For productionization, three high-value trigger moments:

  1. On match initiation — when creator applies or business invites. Premium scoring before introduction. Highest leverage moment.
  2. On gig post — when business posts a new gig. Surface top 5 creator recommendations. Proactive.
  3. On profile view — when user views a candidate's profile. On-demand match score badge. Discovery experience.

Plus background jobs for cache freshness and regression detection.

12. Eval Framework

Multi-Layer Eval

Golden set

50 hand-labeled match outcomes. Each entry: creator, business, expected outcome (success/failure), expected reasoning theme.

Layer 1 — Accuracy (golden set)

MetricTargetKill threshold
Precision (% of "good match" predictions that were actually good)≥ 75%< 55%
Recall (% of actually-good matches that we surfaced)≥ 65%< 45%
F1 (harmonic mean)≥ 70%< 50%

Layer 2 — Faithfulness (Ragas)

Measures: when the agent's reasoning cites a signal, is that signal actually present in the input data?

from ragas.metrics import faithfulness

score = faithfulness(
    answer=prediction.reasoning,
    context=[creator_data, business_data]
)

# Threshold: faithfulness ≥ 0.85
# Catches hallucinations (agent inventing signals not present in data)

Layer 3 — DeepEval assertions

def test_no_invented_metrics():
    """Agent shouldn't reference data fields that don't exist."""
    output = agent.predict(creator_001, biz_001)
    forbidden_terms = ["instagram_dm", "tiktok_dm", "phone_call",
                       "whatsapp", "personal_email"]  # we don't track these
    for term in forbidden_terms:
        assert term not in output.reasoning

def test_recommended_action_valid():
    """Action must be one of the allowed values."""
    output = agent.predict(creator_001, biz_001)
    assert output.recommended_action in [
        "introduce", "introduce_with_clarification",
        "hold_pending_review", "do_not_introduce"
    ]

def test_probability_in_range():
    """Probability must be in [0, 1]."""
    output = agent.predict(creator_001, biz_001)
    assert 0.0 <= output.success_probability <= 1.0

17. Roadmap

V1 → V2 → V3 Evolution

V1 — Proof of Concept (current)

  • Synthetic data only
  • CLI / function-call interface
  • Single LLM provider (Claude)
  • 3-stage cascade with manual triggers
  • Eval framework + observability
  • Full PM artifact set

V2 — Productionization (pending Onemyle decision)

  • FastAPI service wrapper
  • Pinecone (or managed vector DB) for embeddings at scale
  • Multi-cloud LLM routing (Bedrock primary, OpenAI fallback)
  • Reliability patterns: retries, circuit breaker, graceful degradation
  • Real Onemyle data integration
  • Trigger plumbing: signup hooks, gig post hooks, profile view hooks
